One home for retry / backoff / time helpers

Own analysis, pre-grilling. Speculative — low leverage, real duplication. Fold in opportunistically.

The friction

Four small primitives — "sleep N ms", "exponential backoff with a ceiling", "is this HTTP status retryable", "start of today in UTC" — are each written two-to-five times, and the copies have diverged:

PrimitiveCopiesHow they differ
delay(ms) puzzle-ingestion.service.ts, llm-strategy-runner.service.ts (verbatim new Promise(r => setTimeout(r, ms))) identical — pure copy-paste
exponential backoff puzzle-ingestion.computeBackoff: base·2^n + 0–20% jitter, no cap
runner.modelErrorBackoff: min(cap, base·2^(n-1)), no jitter
*-rpd-resume.rearm: clamp(untilReset, 0, 15min) — not exponential at all		 three different policies; only one has jitter, only one has a cap
REARM_MAX_DELAY_MS = 15 * 60_000 copied verbatim into 4 *-rpd-resume.service.ts files identical (candidate 1 collapses these 4 files anyway)
"is retryable" puzzle-ingestion.isRetryableStatus: 429 || >=500
orchestrator's classifyModelCallError has its own notion of retryability		 overlapping concepts, no shared definition
startOfTodayUtc defined in strategies.ts (a config file, line 601), used by FreeTierUsageService and StrategyService single-homed but misplaced — it is a time util, not a strategy knob

None of these is painful — each copy is a handful of lines and rarely touched. But a policy change ("add jitter everywhere", "cap ingestion backoff", "switch daily reset off UTC") is a multi-file hunt with no single place that defines the intent, and the current divergence is almost certainly unintentional drift rather than deliberate per-call tuning.

Deletion test

Delete the private delay / computeBackoff / isRetryableStatus helpers. They concentrate into one common/ module the callers import. Marginal — the concentration is real but the volume is tiny, which is why this is Speculative, not Strong.

The deepened shape

// backend/src/common/retry.ts
export const delay = (ms: number) => new Promise<void>((r) => setTimeout(r, ms));

export function backoffMs(attempt: number, o: {
  baseMs: number; capMs?: number; jitter?: "none" | "full" | "20pct";
}): number;   // one policy, options make the current three variants explicit choices

export const isRetryableHttpStatus = (s?: number) => s === 429 || (s !== undefined && s >= 500);

// backend/src/common/time.ts  — startOfTodayUtc moves here out of strategies.ts
export function startOfTodayUtc(now?: Date): Date;
export function nextUtcMidnight(now?: Date): Date;   // unifies secondsUntilNextUtcMidnight + friends

Callers import instead of redefining. Each backoff site names its policy ({ baseMs, capMs, jitter: "20pct" }) — so a divergence becomes a visible, reviewed decision rather than an accident of which file it was copied from.

Wins

  • one backoff policy, tuned and tested once
  • divergence becomes explicit (an option value), not implicit
  • startOfTodayUtc lands where a reader would look for it
  • tiny surface — trivial to test exhaustively

Risks

  • low leverage — easy to over-invest relative to the payoff
  • a shared backoffMs that's too flexible is its own shallow module; keep the option set to the three real variants
  • don't unify isRetryable with the orchestrator's model-error classification — different domains that happen to rhyme

Recommendation

Speculative. Not worth a dedicated effort. Do it opportunistically while each file is already open for candidate 1 (*-rpd-resume), candidate 5 (llm-strategy-runner), or any ingestion work — extract the helper in that same change rather than scheduling a pass for it.
